- (override) METRIC VALIDITY FIX (thesis-critical). The PRD's 'recommendation acceptance rate' is degenerate: FR-8.4 auto-trains the top 5 by fit score, so the recommended method is ALWAYS trained and the metric always reads 100%. RESOLUTION: acceptance is measured on DELIBERATE USER CHOICE ONLY - the user explicitly selects the recommended method in comparison mode, or completes a session without overriding it. System-initiated auto-training NEVER counts as acceptance. Backend must distinguish system-initiated from user-initiated method runs. Same fix applies to the diversity counter-metric: only user-initiated selections count. PRD success metrics section must be amended.
- (decision) COMPARISON LAYOUT RESOLVED (row alignment was impossible - each method has a different fixed plot set per FR-4.2, so the intersection is often empty). NEW STRUCTURE: (1) a top SHARED METRICS ROW, genuinely aligned across all method columns, holding the comparable quantities only - CV score mean +/- SD, accuracy or RMSE, training time, and delta % vs the recommended reference column; (2) below it, each method's own fixed plot set flows freely in its column at whatever height it needs, with NO cross-column row alignment attempted or implied. Column widths stay equal; column heights may differ. This is honest about methods not being visually comparable while keeping the numbers strictly comparable.
- (decision) SHARED RESOLUTIONS binding on BOTH spines (so the two fix passes stay consistent): (a) GRID MATH - the 4-column comparison layout and the 320px plot-min-width are arithmetically incompatible below ~1416px. Resolution: 4 columns only at >=1416px; 3 columns 1100-1415px; 2 columns 800-1099px. Panel minimum stays 320px and is never violated. (b) RESPONSIVE/ZOOM - DESIGN.md's 'unsupported below 900px' contradicted the WCAG 200%-zoom claim. Resolution: the page REFLOWS to a single column below 800px rather than being unsupported; charts keep their 320px minimum and scroll horizontally within their own panel only. The a11y claim is now 'reflows to single column, no page-level horizontal scroll', which 200% zoom satisfies. (c) TOP BAR - a real specified element: product title left, single 'Benchmark' text link right, MUI AppBar elevation 0 with a bottom divider (NOT elevated, so DESIGN.md's elevation rule is amended to name the top bar as a third above-plane element). Return navigation from Benchmark is the same top bar, with the title acting as the home link. (d) TABLE NAMING COLLISION - FR-2.2's qualitative artifact is renamed 'Method characteristics table' (theory, no data, always present); FR-5.3's empirical artifact keeps 'Comparison results'. The two names never overlap.
- (decision) METRIC AFFORDANCE GAP FOUND AND FIXED: FR-5.2 makes the recommended method's chip non-deselectable, so 'user explicitly selected the recommended method' had NO UI affordance - the fixed acceptance metric was unmeasurable as specified. Resolution: a second question on the FR-5.5 prompt, 'Which method would you use?', never pre-filled. Acceptance now splits into Arm A (explicit pick, strong signal) and Arm B (no override, weak signal), reported SEPARATELY. Selector path (promoted-3 vs show-all) is logged as a covariate so the funnel bias is measurable rather than hidden.

Toggle microcopy amended to state this truthfully. FR-5.5 free-text carries a do-not-identify ask. Flagged as an author-level choice (GDPR-relevant for a Spanish TFM).
