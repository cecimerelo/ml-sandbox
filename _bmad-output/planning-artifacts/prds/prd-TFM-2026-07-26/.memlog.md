- (decision) Primary input: propuesta-tfm.md (tutor-approved thesis proposal). Product is an explainable supervised learning method recommender with EDA + results visualization layers and interactive comparison mode.
- (decision) Form-factor: web application. Target user: anyone wanting to explore/compare ML models (students, practitioners, researchers) — general playground audience, not just ISLR students.
- (decision) Methods in scope: all supervised learning methods from ISLRv2 — Linear/Ridge/Lasso/PCR/PLS regression, Polynomial/Spline/GAM non-linear regression, Logistic/LDA/QDA/NaiveBayes/KNN classification, Decision Trees, Bagging/RF/Boosting/BART ensembles, SVM, Neural Networks (MLP).
- (decision) Scope decision: v1 = supervised learning only. Unsupervised methods (PCA, K-Means, Hierarchical Clustering) deferred to v2 as explicit future work. Survival analysis out of scope entirely.
- (decision) Vision origin: tool born from author's own learning journey during the master's program — struggled to understand which supervised method to use for each problem. This motivates both the pedagogical framing and the target user definition.
- (decision) Target users: (1) Learner — mid-course, knows methods exist but can't map them to problems; (2) Practitioner — has a real dataset, wants quick sanity-check + visual evidence; (3) Explorer — curiosity-driven, wants to play; (4) Instructor — classroom demonstration use case. Form must educate as it asks (tooltip/inline explanations), no assumed ML background required.
- (decision) Research bibliography saved to research-bibliography.md. 14 sources found via web search. All marked [FOUND] — agent located but did not deeply read full papers. Ceci wants to read them herself. Key sources to prioritize: Rice 1976 (foundational), Rivolli 2022 (meta-features survey), AMLBID paper (baseline comparator from proposal), sklearn flowchart, Azure ML cheat sheet.
- (decision) Form is adaptive: if dataset uploaded, auto-compute row count, feature count, feature types, missing value rate, AND prediction type (regression/classification from target column). User confirms auto-detected values. Manual questions only shown when no dataset is uploaded.
- (decision) Form additions: (1) opt-in toggle 'let the tool use column names to improve suggestions' — shown only when dataset uploaded, default on; (2) new always-ask question about feature interactions. When column names opt-in is on, tool suggests likely interactions from column semantics rather than relying solely on user input.
- (decision) Form: when dataset uploaded, ask user to select target column via dropdown (list all column names). Prediction type, class balance, and interaction suggestions are all derived from that selection downstream.
- (decision) Recommendation engine: hybrid — ISLR heuristics (rule-based) + benchmark-trained model. Explanations are tool-agnostic (no ISLR book references in UI, concepts only). Feedback modal added: user can rate whether recommendation was useful after seeing results.
- (decision) Feedback feature: v1, low priority. Backend required to store feedback from multiple users. Backend decision also has implications for where ML training/inference runs (client vs server).
- (decision) Data privacy: user dataset stored temporarily for session duration only, deleted on session end. Never persisted to long-term storage. Only feedback responses (no raw data) are stored permanently.
- (decision) EDA layer (dataset required): distribution plots per feature, correlation heatmap, outlier detection (boxplots), target variable distribution. Shown before recommendation to motivate it.
- (decision) Results flow: EDA shown as first step of results (before recommendation + model results) so user can follow the full process. Method-specific visualizations defined per method with fixed mapping. User can add extra plots. Decision boundaries auto-pick 2 most important features, user can swap.
- (decision) UX: single-page dashboard layout (not a step-by-step wizard). EDA section is collapsible/expandable — collapsed by default so it doesn't dominate, but accessible. Recommendation + model results always visible.
- (decision) Dashboard updates on explicit 'Get Recommendation' button click only — not live/reactive. Avoids expensive retraining on every form change.
- (decision) Comparison mode: capped at 4 methods total (recommended + 3 alternatives). Shows winner call after comparison ('based on your dataset, X outperformed the recommendation by Y%'). Winner call has its own feedback prompt — separate from the recommendation feedback.
- (decision) Benchmark: OpenML-CC18 (classification, primary) + UCI (regression, supplementary). Benchmark results exposed in UI via dedicated page showing dataset×method performance heatmap, heuristic vs empirical agreement, and per-row error reporting for corrections.
- (decision) NFRs confirmed: 50MB max upload, <5s recommendation (no dataset), 60s training timeout with loading indicator, modern browsers only, CSV only, max 500 features, numeric/categorical only, no auth, no SLA, datasets deleted on session end, only anonymized feedback stored.
- (decision) Hyperparameter tuning: deferred to v2 but flagged as highest priority post-MVP feature. Not part of v1 scope.
- (decision) Success metrics v1: (1) Research/accuracy — top-1 hit rate, regret, Spearman rank correlation; (2) User satisfaction — % positive on recommendation feedback, % agreeing with winner call; (3) Accuracy/quality — % recommended method in top-3 on benchmark, % heuristic/empirical agreement; (4) Counter-metrics — recommendation diversity across problem types, tool should not always recommend most complex method.
- (decision) Revised data policy: datasets processed in memory only, never stored. Backend permanently stores (anonymized): decision drivers (form answers + auto-detected metadata), system recommendation, method(s) actually run by user, feedback ratings + comments. Whether user followed recommendation is a derived field inferred at query time — not stored explicitly.
- (decision) Satisfaction metrics simplified: no feedback modal in v1 (deferred to v2). Single behavioral metric instead: recommendation acceptance rate (% of sessions where user ran the recommended method). Derived from stored decision drivers — no user self-reporting needed.
- (event) PRD finalized
